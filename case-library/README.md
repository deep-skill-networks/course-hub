# Case library

Anonymised production incidents from real AI systems, written so you can practise diagnosis before reading the answer. Cases come from the mentor's work and from alumni, always with permission and with identifying details removed.

## How to use a case
1. Read the **context** and the **symptoms**. Stop.
2. Write down who is affected, since when, and your top three hypotheses across different layers (data, retrieval, prompt, model, tools, infrastructure, cost controls).
3. Read the **evidence** section and decide which hypothesis survives.
4. Only then read the **root cause**, **fix** and **prevention**.

The method we use throughout the course is **OHIFP**: Observe → Hypothesise → Isolate → Fix → Prevent. A fix only counts once something automated would catch the same failure next time.

## Contributing a case
Alumni: use the [case template](_template.md) and open a pull request, or send it to the mentor privately for anonymisation. Remove client names, people's names, internal URLs, and any figures that could identify the organisation.
